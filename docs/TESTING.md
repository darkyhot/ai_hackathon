# Тестирование ветки tool_calling_agent и защиты

Проверка 31.10.2026, после слияния: агент на tool calling, доработки nas_features и защита от инъекций. Нужно было проверить три вещи:
- не сломалось ли что-то при переходе с конвейера на агента с действиями;
- держит ли агент инъекции;
- работает ли весь путь клиента в браузере.

## Итоги

| Набор | Как запускать | Результат |
|---|---|---|
| Модульные и интеграционные тесты | `.venv/bin/python -m unittest discover -s tests -t .` | **89 / 89** (было 72; +14 на защиту, +2 на настройки моделей, +1 на старую базу) |
| Сквозные сделки через API | `.venv/bin/python -m tests.e2e.scenarios` | **4 / 4** до подписания |
| Сквозная проверка в браузере (Chromium, Playwright) | `.venv/bin/python -m tests.e2e.browser_flow` | **26 / 26** |

## Как устроена сквозная проверка без сети

В песочнице, где шла проверка, не было доступа ни к DeepSeek/GigaChat, ни к Циану. Поэтому сделан тестовый сервер `tests/e2e/server.py`. Это настоящий `backend.main` (тот же FastAPI, база, действия агента, фронтенд), но:
- **модель** — `tests/e2e/policy_llm.py`. Это «дублёр», который по правилам ведёт агента обычным ходом сделки. Он вызывает те же действия (tools), что и настоящая модель, видит их результаты и состояние сделки из системного промпта. Это не режим продукта, только для тестов;
- **Циан** — сохранённые настоящие объявления из `tests/e2e/data` (Казань вторичка и новостройки, Москва), без телефонов продавцов;
- **карта** (OpenStreetMap) недоступна, как без сети.

Так проверяется всё, кроме качества ответов самой модели и живого Циана. Их нужно проверить вручную с ключом (см. README, раздел «Проверить самому»).

## Что проверено

### Модульные тесты (`tests/`)
- `test_agent.py`, `test_llm_and_agent.py`: цикл агента, действия, ипотека, накопления, торг, звонок, просмотр, сделка, клиенты DeepSeek и GigaChat (формат tool calling).
- `test_chats_auth.py`: диалоги, история, возврат, регистрация и вход, чужой диалог не открыть.
- `test_cities.py`, `test_mortgage.py`, `test_refresh.py`, `test_store.py`: города, программы ипотеки, ночной обход, база объявлений.
- **Новое, `test_guard.py`** (14 тестов):
  - 44 атаки по шести категориям блокируются с правильной категорией;
  - 30 обычных фраз клиента проходят без ложных срабатываний;
  - фильтр выхода ловит «канарейку», куски промпта, ключи, хеши, повторы и длину;
  - `sanitize` убирает команды из описаний объявлений;
  - **инъекция не доходит до модели**: проверяется по тому, что модель реально получила, а не по ответу;
  - текст модели с утечкой заменяется безопасным;
  - результаты действий очищаются;
  - HTTP: заголовки, SQL-инъекции во входе (`' OR 1=1 --`, `admin'--`, `DROP TABLE`), лимит частоты, пауза после 5 атак, инъекция от «продавца».
- **Новое, `ProviderConfigTest`**: ключ DeepSeek без `sk-` дополняется; адрес GigaChat по умолчанию — `https://api.giga.chat/v1`.

### Сквозные сделки через API (`tests/e2e/scenarios.py`)
Четыре клиента проходят путь от запроса до подписания. Проверяются карточки подтверждения, панели этапов и отсутствие ошибок:
1. Казань, вторичка, наличные.
2. Семья: сын 4 года, маткапитал, копит на взнос (семейная ипотека и стратегия накоплений).
3. Москва, ипотека, взнос есть.
4. Казань, новостройки и вторичка.

### Браузер (`tests/e2e/browser_flow.py`)

## Что изменилось при слиянии и не возвращалось

При переходе на tool calling напарник сознательно убрал части nas_features. Они остались в истории ветки nas_features, и их можно вернуть отдельно:
- демо-режим и демо-данные;
- админские эндпоинты;
- речевая аналитика звонка;
- окно проверки по госреестрам (`security.py`);
- документы ERD, ARCHITECTURE, NAS_FEATURES.

Этап «Проверка» в новой версии — это риски по данным объявления, а не окно с госреестрами.

## Как повторить сквозную проверку

```bash
# один раз: браузер для Playwright
.venv/bin/pip install playwright && .venv/bin/playwright install chromium

# терминал 1 — тестовый сервер (база во временной папке, сеть не нужна)
.venv/bin/python -m tests.e2e.server --port 8790

# терминал 2
.venv/bin/python -m tests.e2e.scenarios --base http://127.0.0.1:8790
.venv/bin/python -m tests.e2e.browser_flow --base http://127.0.0.1:8790 --shots /tmp/shots
```

Скриншоты (сделка, инъекции, телефон) сохраняются в `/tmp/shots`. Сценарий B ставит свой диалог на паузу: так и задумано. Повторный запуск через пару минут или после перезапуска сервера проходит снова.
