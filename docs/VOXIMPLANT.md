# Миграция звонков с МТС Exolve на Voximplant

Ноябрь 2026. Ветка `voximplant` от актуального `main`.

## 1. Где и зачем был Exolve

В проекте Exolve отвечал только за режим «Позвонить мне на телефон», где агент звонит на настоящий номер, а продавца играет человек.

| Задача | Как было на Exolve | Файлы |
|---|---|---|
| Звонок продавцу | Звонил **браузер**: JsSIP по WebRTC регистрировался на `webrtc.exolve.ru` с логином и паролем SIP ID и набирал номер. Браузер сначала узнавал свой внешний IP (`/client-info`), иначе 403 | `frontend/js/phone.js`, `frontend/vendor/jssip.esm.js` |
| Голос агента в линии | `/api/tts`: сервер вызывал Media API `media/v1/Synthesize` (WAV), браузер проигрывал звук в WebRTC-поток (AudioContext). Особая возня с Safari: контекст создавался прямо в нажатии | `backend/phone.py` → `synthesize`, `frontend/js/phone.js` |
| SIP-доступ | `/api/phone` брал по API пароль SIP ID и **отдавал его браузеру** | `backend/phone.py` → `credentials` |
| Распознавание ответа продавца | **Не Exolve**: браузер записывал звук продавца из WebRTC и слал его на `/api/stt` (локальный Whisper) | `frontend/js/voice.js`, `backend/stt.py` |
| Речевая аналитика | **Не Exolve**: после звонка модель выписывает из расшифровки факты и поправки к объявлению (`extract_call`), а правила проверяют правдоподобие. В старой ветке nas_features был ещё модуль на правилах `call_analytics.py`, в `main` его нет | `backend/agent/negotiation.py` |

Exolve в проекте делал две вещи: SIP-звонок из браузера и синтез речи. Распознавание и аналитика с ним связаны не были, они работают с текстом расшифровки.

## 2. Покрывает ли Voximplant всё это

Да, и закрывает это даже лучше: все голосовые задачи уходят в облако.

| Потребность | Voximplant | Проверено |
|---|---|---|
| Звонок на российский номер | `VoxEngine.callPSTN(номер, callerid)` в сценарии. Callerid — арендованный номер Voximplant или подтверждённый свой | типы VoxEngine, тест сценария |
| Голос агента (TTS) | `call.say(text, {voice})`, русские голоса SaluteSpeech (Сбер), T-Bank, Yandex, Google, Microsoft. По умолчанию `VoiceList.SaluteSpeech.ru_RU_sergey` | `VoiceList` в типах VoxEngine 37 |
| Распознавание продавца (ASR) | `VoxEngine.createASR({profile})` + `call.sendMediaTo(asr)`: в распознавание идёт только голос продавца. Профили `SaluteSpeech.ru_RU`, `Yandex.ru_RU`, `TBank.ru_RU` | `ASRProfileList` в типах |
| Управление звонком из браузера | Web SDK: `client.call()` в сценарий, текст в обе стороны через `Call.sendMessage` ↔ `CallEvents.MessageReceived` | `voximplant.d.ts` Web SDK 4.15 |
| Безопасный вход браузера | Вход по одноразовому ключу: `requestOneTimeLoginKey` → сервер считает `MD5(key + "\|" + MD5(user + ":voximplant.com:" + password))` → `loginWithOneTimeKey`. Пароль не покидает сервер | формула из документации SDK |
| Настройка без кабинета | Management API: `AddApplication`, `AddScenario`/`SetScenarioInfo`, `AddRule`, `AddUser`/`SetUserInfo`, `GetPhoneNumbers`, `GetCallerIDs` | официальный клиент `@voximplant/apiclient-nodejs` 5.1 |
| Речевая аналитика | Наша аналитика работает по тексту и не меняется. Расшифровку теперь даёт ASR Voximplant, а не Whisper. При желании у Voximplant есть запись с транскрибацией (`call.record`), но мы её **не включаем**: голос продавца — персональные данные, решили их не хранить | — |

Что стало лучше по сравнению с Exolve:
- **Пароль больше не уходит в браузер.** На Exolve браузер получал пароль SIP ID, теперь вход идёт по одноразовому ключу.
- **Звук не проходит через страницу.** Нет AudioContext, нет хитростей с Safari, не нужен микрофон и не нужно узнавать внешний IP. Звонок не рвётся, если Safari приостановил звук.
- **Ответ продавца распознаётся в облаке на лету.** Аудио больше не надо записывать в браузере и отправлять на Whisper. Если продавец ответил, пока агент говорил, ответ не теряется.
- **Настройка в один шаг.** Приложение, сценарий, правило и пользователя сервер создаёт сам по ключу из `.env`.
- **Сценарий сам кладёт трубку через 10 минут**, чтобы забытая линия не тратила деньги.

## 3. Как устроено теперь

```
браузер (phone.js, Web SDK)                     облако Voximplant                      телефон продавца
  ├─ GET  /api/phone ─────────── сервер: настройка приложения, имя пользователя, номер, узел
  ├─ requestOneTimeLoginKey ─▶ ключ
  ├─ POST /api/phone/login {key} ── сервер: хеш с паролем
  ├─ loginWithOneTimeKey
  ├─ call("seller", customData={to, callerid, voice, asr}) ─▶ scenario.js ── callPSTN ─▶ звонит
  │                                               ◀─ ringing / answered
  ├─ sendMessage {"type":"say","text":…} ───────▶ call.say (синтез) ─────────────────▶ слышит агента
  │                                     ◀─ said    ◀─ ASR ◀───────────────────────────── отвечает
  ◀─ {"type":"heard","text":…} ─▶ агент (/api/session/{id}/seller)
  └─ hangup ───────────────────────────────────▶ кладёт трубку, terminate
```

- `backend/voximplant/scenario.js` — сценарий VoxEngine: набор, очередь реплик, распознавание, ограничения (номер только российский, реплика до 1500 символов, один звонок на сессию, 10 минут).
- `backend/phone.py` — Management API (ключ API или JWT сервисного аккаунта), идемпотентная настройка, хеш входа, выбор номера и узла.
- `frontend/js/phone.js` — тот же интерфейс `PhoneCall` (`dial`, `say`, `listen`, `filler`, `hangup`), что был у Exolve, поэтому остальной фронтенд почти не менялся.
- `frontend/vendor/voximplant.min.js` — Web SDK 4.15.0 (Apache-2.0). Загружается, только когда нужен звонок.
- Удалены JsSIP, `/api/tts`, `EXOLVE_*`.

## 4. Что сделать на второй итерации (с ключом)

1. **Кабинет** — `manage.voximplant.ru`:
   - пополнить баланс;
   - арендовать номер (Номера → Купить) или подтвердить свой (Настройки → Caller ID). Тестовые номера для `callPSTN` не подходят, так сказано в документации.
2. **`.env`**:
   ```
   VOXIMPLANT_ACCOUNT_ID=…        # главная кабинета, «Данные для API, SDK, SIP»
   VOXIMPLANT_API_KEY=…           # Настройки → API-ключи
   # или VOXIMPLANT_CREDENTIALS=/путь/к/сервисному_аккаунту.json (файл в git не попадёт)
   VOXIMPLANT_CALLER_ID=          # если номеров несколько или используете подтверждённый свой
   PHONE_PIN=…                    # обязательно на публичном сервере
   ```
3. `pip install -r requirements.txt` (добавлен `pyjwt[crypto]` для сервисного аккаунта).
4. `.venv/bin/python -m backend.phone`. Команда должна показать аккаунт, баланс, приложение с узлом (например, `NODE_4`), пользователя и номер. Если API ответит ошибкой адреса, посмотрите адрес API в российском кабинете и укажите его в `VOXIMPLANT_API_HOST`. Если узел «не определён», возьмите его с главной кабинета и впишите в `VOXIMPLANT_NODE`.
5. Запустить сервер, на шаге «Звонок» нажать «Позвонить мне на телефон», ввести свой номер, взять трубку.
6. Что проверить ушами:
   - **Голос агента.** По умолчанию SaluteSpeech «Сергей». Поменять можно в `VOXIMPLANT_VOICE`, например `SaluteSpeech.ru_RU_boris`, `Yandex.Neural.ru_RU_alena`, `TBank.ru_RU_Dima`.
   - **Качество распознавания.** Если хуже Whisper, поменяйте `VOXIMPLANT_ASR` на `Yandex.ru_RU` или `TBank.ru_RU`.
   - **Паузы** между репликами.
7. Если что-то не так, смотрите логи сессии: кабинет → История звонков → сессия → лог сценария. Там видно, что сценарий получил и что ответил.

Что я проверить не мог (нет ключа и доступа к облаку из песочницы):
- реальный вход Web SDK;
- настоящий звонок;
- звучание голоса;
- точность распознавания;
- адрес API для российского аккаунта.

Интерфейсы сверены с официальными пакетами Voximplant (Web SDK 4.15.0, типы VoxEngine 37.0.0, клиент Management API 5.1.0). Настоящий Web SDK проверен в Chromium: все нужные методы и события на месте.
