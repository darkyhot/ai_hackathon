# Агент сделки — ИИ-агент «жизненных событий» для Домклик

Прототип для хакатона (номинация ROI). Клиент голосом или текстом описывает, какую квартиру ищет: город, бюджет, комнаты, пожелания. Дальше работает **агент**: модель сама решает, что делать, — выбирает действия (записать запрос, посчитать ипотеку, найти, показать подборку, позвонить продавцу, оформить сделку), видит их результат и решает дальше. Числа считает код, рамки (бюджет, лимит торга, подтверждения клиента) держит код. Агент:

1. **Уточняет**, если не хватает города, бюджета или числа комнат.
2. **Финансовый помощник** подбирает ипотечную программу (рыночная или семейная с 01.10.2026, маткапитал во взнос) и по доходам, расходам и накоплениям строит стратегию накопления первоначального взноса на продуктах Сбера (накопительный счёт, вклад, облигации и фонды в СберИнвестициях) с учётом срока, ежемесячных пополнений и отношения к риску.
3. **Ищет реальные объявления на Циане** — вторичку и новостройки, 105 городов — и считает справедливую цену по ближайшим похожим квартирам. Всё увиденное копит в своей базе вместе с признаками.
4. **Подбирает с обратной связью**: клиент отмечает «Нравится / Не то» и пишет пожелания — агент учитывает это в следующей подборке. Пожелания вроде «с балконом и гардеробной» проверяет по объявлению, а «рядом школа / поликлиника / парк» — по 2ГИС и OpenStreetMap; квартиры показывает на карте.
5. **Проверяет риски** по данным объявления.
6. **Звонит продавцу**: уточняет то, чего нет в объявлении, торгуется в рамках клиента и договаривается о просмотре.
7. Дальше — просмотр, план сделки (ипотека, страхование, СБР или ДДУ с эскроу, электронная регистрация) и итог: экономия клиента и доход Сбера.

В любой момент можно спросить («что такое эскроу?», «сколько я переплачу?») — агент ответит с числами этой сессии. Диалоги сохраняются: к любому можно вернуться и продолжить, после входа — с любого устройства.

## Запуск

Установка одной командой — окружение, пакеты, модель распознавания речи Whisper small (~460 МБ) и `.env` из шаблона:

```bash
./scripts/setup.sh
```

Потом впишите в `.env` ключ `DEEPSEEK_API_KEY` (или настройки GigaChat) и запустите:

```bash
.venv/bin/uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

Откройте http://localhost:8000.

Интерфейс «Место» использует общую шапку и оформление на всех страницах. «Квартиры» открывает поиск по параметрам, «Новостройки» выбирает соответствующий рынок, «Умный поиск» — отдельный запрос своими словами. В истории есть сохранённые подборы, поиск и фильтры статусов; выбранный диалог открывается с прежними сообщениями и решениями. На телефоне чат сворачивается, освобождая место подборке. Исходная папка `дизайн/` для работы не нужна. Все карточки, подтверждения и объявления поступают из рабочего API.

Оформление ветки `ux/ui` адаптировано в `frontend/approved-design.css` и компонентах карточек: подтверждения — в основной области, принятые решения — в истории, навигация — в списке «Этапы сделки». Существующие сценарии и API сохранены; детали переноса и проверки — [docs/UI_MIGRATION.md](docs/UI_MIGRATION.md).

Общая оболочка находится в `frontend/shell.css`, навигация — в `frontend/js/shell.js`. Переходы между главной, историей, текущим подбором и экономикой не создают новый диалог. У страниц свои адреса (`#apartments`, `#history`, `#chat-…`, `#economics`); работают перезагрузка и кнопки браузера назад/вперёд. Новый подбор начинается после отправки формы, повторная отправка во время запуска блокируется.

Варианты установки:
- `WHISPER_MODEL=base ./scripts/setup.sh` — модель поменьше (~140 МБ), если интернет медленный; тогда же поставьте `WHISPER_MODEL=base` в `.env`.
- `SKIP_WHISPER=1 ./scripts/setup.sh` — без модели: голос будет распознавать браузер (Chrome/Edge, нужен доступ к их облаку).
- Модель отдельно: `.venv/bin/python -m backend.stt download`. Если Hugging Face качает медленно, четыре файла (`model.bin`, `config.json`, `tokenizer.json`, `vocabulary.txt`) с https://huggingface.co/Systran/faster-whisper-small можно скачать браузером в папку `models/faster-whisper-small` и указать путь в `WHISPER_MODEL`.

Сервер сам модель не качает: если её нет, микрофон работает через браузер, а `/api/health` подсказывает команду для загрузки.

Тесты (без сети): `.venv/bin/python -m unittest discover -s tests -v`

Нужен ключ модели (DeepSeek или GigaChat): без модели агент не работает и честно об этом говорит — запасных сценариев «без модели» нет. Тесты используют поддельную модель по сценарию (`tests/fakes.py`).

### Перед демо: прогреть срез объявлений

Если на площадке Циан ответит капчей, агент возьмёт базу и последний сохранённый срез (это тоже реальные объявления). Прогрев заполняет и то, и другое (`--new` — новостройки):

```bash
.venv/bin/python -m backend.sources.cian --city Казань --rooms 2 --budget 9000000 --pages 2
```

Срезы лежат в `backend/data/cache/`, база — в `backend/data/app.db`; в git не попадают.

## Разговор голосом (без кнопок)

Кнопка «Разговор» под полем ввода включает диалог голосом: микрофон слушает сам, после паузы в речи (~1 с) фраза уходит агенту, ответ звучит голосом браузера. Пока агент говорит, микрофон не слушает; нажатие на кружок перебивает агента (или отправляет фразу, не дожидаясь паузы). «Стоп» или «Завершить» выключают режим.

Голосом можно всё, что делается кнопками: «да» / «изменить» на карточках, «наличными» / «ипотека, взнос есть» / «копим», «позвони мне» / «продавца сыграет ИИ» / «продавец я», в подборке — «вторая нравится», «первая и третья не то» и «звони». Карточки подборки пронумерованы. Если в звонке продавец — вы, ваши ответы идут продавцу; во время звонка на телефон режим ждёт. Распознавание — Whisper на сервере, без него — браузер (Chrome/Edge).

## Аккаунты и история диалогов

Кнопка «Диалоги» в чате — список разговоров, как в чат-ботах: новые сверху, любой открывается со всей историей и продолжается. У диалога своя ссылка `/#chat-<id>`.

- **Без регистрации** диалоги привязаны к браузеру (cookie `vid`). После входа или регистрации («Войти» в шапке) они переходят в аккаунт и открываются с любого устройства.
- **Закрытая вкладка агента не останавливает.** Каждое событие диалога пронумеровано и записано в базу; открыли снова — сначала приходит история (без голоса и пауз), потом живые события. Связь оборвалась — браузер переподключается с того же места.
- **Продолжить законченный диалог** можно сообщением: «а если трёшку?» — новый поиск с тем, что агент уже знал (город, бюджет, семья), вопрос («сколько я переплачу?») — просто ответ. После перезапуска сервера диалог продолжается так же.
- Чужой диалог не открыть: каждый запрос проверяет владельца (браузер или пользователь). Пароли — scrypt, в базе только хеш токена входа, 5 неверных паролей — пауза 10 минут. Брошенные сессии освобождают память сами (история остаётся в базе).

## База объявлений агента и ночной обход

Всё, что агент видит на Циане вживую, он записывает в базу: объявление, историю цены и **признаки** — балкон и лоджия, санузел, гардеробная, парковка (из полей площадки и описания) и «что рядом» по карте (школа, поликлиника, парк, вода… — из OpenStreetMap, раз в месяц). Признаки считаются один раз и нужны всем, кто ищет похожее:

- проверка «что рядом» для уже известной квартиры — мгновенно вместо 5–90 секунд у Overpass;
- в подборку сразу добавляются подходящие объявления из базы, которые агент видел за неделю, — меньше страниц Циана на редкие пожелания; если Циан недоступен, подбор идёт по базе;
- справедливая цена считается по всем известным аналогам за месяц, а не только по текущей выдаче.

Перед звонком агент открывает страницу объявления: снятое («Объявление снято с публикации») — честно говорит и переходит к следующему, в базе помечает снятым; живое — обновляет параметры по свежей странице (цена, площадь, кухня, этаж, описание), а если цена изменилась — говорит и торгуется от новой.

**Уточнения продавца.** После звонка модель выписывает параметры, которые продавец прямо назвал и которые уточняют объявление или расходятся с ним («кухня 12 м², в объявлении ошибка», «балкона нет»); код отбрасывает неправдоподобное и совпадающее с объявлением. Уточнения хранятся отдельно от данных площадки (источник `call`) и при каждом чтении накладываются поверх: ни обход, ни новый поиск их не перезаписывают, перезаписать может только следующий звонок. На карточке — «Со слов продавца: кухня 12 м² (в объявлении — 18 м²)». Слова ИИ-продавца (симуляция) действуют только в этом диалоге и в общую базу не попадают. Историю храним только для цены. Каждую ночь обход (`REFRESH_AT=04:00` в `.env` или `python -m backend.workers.refresh --once`) проходит поиски, которые задавали клиенты: новые объявления и изменения — в базу, пропавшие из выдачи — открывает страницу: снято — помечает, живо — обновляет параметры. Неполный обход (капча, сеть) ничего не снимает. Итоги последнего обхода видны на экране поиска.

База — SQLite в `backend/data/app.db` (в git не попадает); для прода — PostgreSQL через `DATABASE_URL`.

## Настоящий звонок на телефон (Voximplant)

Агент звонит на указанный номер и разговаривает голосом: уточняет детали, торгуется, договаривается о просмотре. Продавца играете вы. Почему Voximplant и что поменялось по сравнению с МТС Exolve — [docs/VOXIMPLANT.md](docs/VOXIMPLANT.md).

Как устроено: звонит облако Voximplant. Браузер входит в приложение Voximplant (Web SDK) и «звонит» в сценарий VoxEngine (`backend/voximplant/scenario.js`). Сценарий набирает продавца, произносит реплики агента (синтез речи SaluteSpeech) и распознаёт его ответы (распознавание SaluteSpeech). Браузеру уходит только текст, звук на странице не играет, микрофон не нужен. Страница должна оставаться открытой: через неё агент получает ответы продавца.

Настройка:
1. В [личном кабинете Voximplant](https://manage.voximplant.com): пополнить баланс и арендовать номер (Номера → Купить) или подтвердить свой номер как Caller ID (Настройки → Caller ID).
2. В `.env`: `VOXIMPLANT_ACCOUNT_ID` и `VOXIMPLANT_API_KEY` (Настройки → API-ключи) или путь к JSON сервисного аккаунта в `VOXIMPLANT_CREDENTIALS`. По желанию: `VOXIMPLANT_CALLER_ID` (если номеров несколько), `VOXIMPLANT_VOICE` и `VOXIMPLANT_ASR` (голос и распознавание), `SELLER_PHONE` (номер по умолчанию).
3. Проверка: `.venv/bin/python -m backend.phone`. Команда покажет аккаунт, баланс и номер для звонков, а заодно создаст или обновит приложение `domclick-agent`, сценарий, правило и пользователя. Руками в кабинете ничего создавать не нужно. При первом звонке сервер делает то же самое сам.
4. На шаге «Звонок» нажать «Позвонить мне на телефон», ввести номер, взять трубку.

**Ключи** живут только в `.env` на сервере. Браузер получает имя пользователя приложения, но не пароль: вход идёт по одноразовому ключу, хеш считает сервер (`/api/phone/login`). **На публичном сервере всё равно задайте `PHONE_PIN`**: без него любой посетитель сайта сможет запустить звонок за ваш счёт.

Чтобы звонок шёл быстрее: браузер входит в Voximplant, пока на экране карточка звонка; ответ продавца с ценой разбирается правилами без запроса к модели; пока агент думает, он говорит короткое «Так, понял.». Разговор не записывается: голос продавца нигде не хранится, в журнал сделки попадает только текст. Сценарий сам кладёт трубку через 10 минут.

Ограничения: разговор по очереди, перебить агента нельзя. Если продавец ответил, пока агент говорил, ответ не теряется и уходит агенту. Ответ агента приходит через 2–4 секунды. Если ответ не распознался, его можно вписать вручную.

## Откуда объявления

Официального API для поиска по чужим объявлениям у Циана, Домклика и Авито нет: их API — для продавцов и агентств (свои объявления, фиды, входящие чаты). Поэтому:

- **Циан** — данные со страницы выдачи поиска (вторичка и новостройки: ЖК, срок сдачи, застройщик, ДДУ или уступка), без телефонов продавцов; фото — ссылкой на оригинал. Запрос — по просьбе клиента или ночным обходом, 1–3 страницы, не чаще раза в 3 секунды. Сначала обычный HTTP-запрос; если Циан ответил капчей, 403 или заглушкой защиты от ботов — повтор через `curl_cffi` с TLS-отпечатком Chrome; если и он не прошёл — база агента и сохранённый срез. 105 городов (коды регионов; семь проверены на живом Циане). Если Циан переводит город на свой поддомен (kaluga.cian.ru), агент идёт за ним и запоминает.
- **Домклик и Авито** — с этого компьютера не открываются (VPN с нидерландским IP: Авито блокирует по IP, Домклик закрыт защитой Qrator). Путь — отдельный сервис на сервере с российским IP; см. [ROADMAP](docs/ROADMAP.md).

Это серая зона: пользовательские соглашения площадок, скорее всего, запрещают автоматический сбор. Для прототипа с единицами запросов риск невелик; для продукта правильный источник — данные Домклика внутри Сбера.

## Что настоящее, а что симуляция

| Часть | Сейчас |
| --- | --- |
| Объявления, цены, площади, фото, районы, метро | Реальные (Циан) |
| Что рядом с домом | Реальные данные OpenStreetMap (Overpass API, без ключа, живой запрос): школа, детский сад, поликлиника, больница, парк, вода (реки, озёра, пруды), аптека, магазин, ТЦ, фитнес в радиусе 1 км. Один запрос на пачку до 25 квартир, обычно 5–40 с; ответы кэшируются. Если сервис не ответил, агент так и говорит и помечает карточки «Не проверено по карте». Карта — Leaflet с плитками CARTO |
| Удобства (балкон, гардеробная, парковка…) | По полям и описанию объявления. В подборку попадают только квартиры, где пожелание подтверждено; если таких нет — агент честно говорит «в бюджете нет, есть на X дороже» или «таких нет совсем» и предлагает поднять бюджет или убрать условие |
| Справедливая цена | Медиана цены м² до 8 ближайших похожих квартир (по координатам, площадь ±30%) с поправками на ремонт, год, этаж; −3% на торг; коридор — межквартильный размах |
| Звонок продавцу | Три режима: ИИ играет продавца со скрытой минимальной ценой; «продавец — я» в чате; **настоящий звонок на телефон** через Voximplant (продавца играете вы). Настоящим продавцам с Циана прототип не звонит |
| Проверка рисков | По данным объявления (проверка Росреестром на Циане, апартаменты, торги, слова «доля», «наследство», «перепланировка»). Выписки ЕГРН/ФССП/ЕФРСБ не подключены |
| Финансовый план | Расчёт настоящий; ставки и доходности продуктов — допущения; «Открыть продукт» — демо |
| Ипотека | Рыночная ставка Сбера от 15,5% (при взносе меньше 30% — 17,5%) и семейная ипотека по условиям с 01.10.2026: ребёнок до 7 лет, ставка и лимит по числу детей, вторичка — только где почти не строят. Маткапитал — во взнос. Платёж — у каждой квартиры по подходящей ей программе. Ставки — открытые данные на октябрь 2026; итог дала бы предодобрение Сбера |
| История диалогов и аккаунты | Настоящие: база SQLite/PostgreSQL, cookie, вход по почте и паролю. Вход через Сбер ID — нет |
| База объявлений, ночной обход, проверка «не снято» | Настоящие (Циан, OpenStreetMap) |
| Ответы на вопросы | Модель отвечает с числами сессии; без модели агент честно говорит, что ответить не может |

## Архитектура

```
frontend/                статичный UI без сборки (HTML + CSS + ES-модули)
  js/app.js              контроллер: SSE-события -> чат, степпер, панели; повтор истории диалога; голосовой ввод
  js/chats.js            список диалогов: открыть, продолжить, новый
  js/account.js          вход и регистрация, уведомление о cookie
  js/views.js            панели этапов: финансы, подборка, проверка, просмотр, сделка, итог
```

Принцип: **модель решает, код считает и держит рамки.** Агент сам выбирает действия и их порядок; действие, которое нарушает рамки (поиск без подтверждённых рамок или до расчёта ипотеки, звонок без рамок, подтверждение цены без звонка, подписание без выбранной квартиры), не выполняется и возвращает модели объяснение, что сделать сначала. В торге модель формулирует реплики, а код не даёт агенту предложить больше лимита клиента или отступить назад, а ИИ-продавцу — уйти ниже скрытой минимальной цены. Модель не ответила — агент так и говорит и продолжит, когда клиент напишет; память агента хранится в базе, поэтому после перезапуска сервера диалог продолжается с того же места.

### Ограничения активной работы и очередь модели

Один ход агента ограничен 120 секундами активной работы (`AGENT_TURN_TIMEOUT_S`). Ожидание ответа на карточке и реплики живого продавца не входит в этот срок. Сохраняется предел 14 действий подряд; третье подряд одинаковое действие без нового ответа клиента останавливается. При остановке незавершённые вызовы закрываются в памяти модели, условия поиска сохраняются: можно написать «продолжить».

GigaChat выполняет одну генерацию на процесс и принимает до 6 ожидающих запросов (`GIGACHAT_QUEUE_SIZE`). На ожидание даётся 25 секунд (`GIGACHAT_QUEUE_TIMEOUT_S`), на весь вызов модели после очереди, включая OAuth и повторы, — 60 секунд (`LLM_CALL_TIMEOUT_S`, также для DeepSeek). В интерфейсе видно ожидание; при переполнении или истечении срока агент предлагает повторить позже. Ограничения действуют на один процесс, не являются распределённой очередью и не заменяют ограничение входного трафика.

Логгер `agent.runtime` пишет JSON-записи с ID диалога/хода, именем инструмента, длительностью активной работы и ожидания, результатом или классом ошибки. Тексты сообщений, аргументы инструментов, ключи и тело ошибки провайдера в эти записи не включаются. Для LLM-вызовов есть отдельные записи, в том числе внутри переговоров; `llm_operations` в итоге хода считает верхнеуровневые обращения оркестратора. Это диагностика демо, без отдельной системы мониторинга и подсчёта стоимости токенов.

## Переключение на GigaChat

В `.env`:

```
LLM_PROVIDER=gigachat
GIGACHAT_CREDENTIALS=<Authorization Key из личного кабинета, без Basic>
GIGACHAT_SCOPE=GIGACHAT_API_PERS        # или GIGACHAT_API_B2B / GIGACHAT_API_CORP
GIGACHAT_MODEL=GigaChat-2-Max
GIGACHAT_VERIFY_SSL=true
```

Если выданы Client ID и Client Secret, ключ авторизации — base64 от строки `Client ID:Client Secret`. Секреты храните только в `.env`. После смены провайдера перезапустите backend.

Корневой сертификат НУЦ Минцифры включён в `backend/certs/` и добавляется только в SSL-контекст GigaChat. Проверка TLS включена; при необходимости свой файл задаётся через `GIGACHAT_CA_BUNDLE`. Клиент сохраняет `functions_state_id` в памяти диалога и при восстановлении из базы. Набор доступных инструментов учитывает состояние сделки, чтобы модель не повторяла уже отвеченные вопросы или поиск до подтверждения рамок.

Подложка карты — **2ГИС Raster Tiles API**, если заполнен `TWOGIS_API_KEY`. Для ключа нужен доступ к Raster Tiles API наряду с каталогом инфраструктуры. Плитки приходят через `/api/map/tiles/{z}/{x}/{y}.png`: ключ остаётся на сервере, кэш ограничен 256 изображениями на пять минут, запросы ограничены по IP. Параметры плиток проверяются; произвольный URL upstream передать нельзя. Leaflet хранится локально в `frontend/vendor/leaflet/`.

Без ключа используется OpenStreetMap; при ошибке 2ГИС карта переключается на OSM с видимым сообщением и сохраняет маркеры квартир. Для каталога парков и школ продолжает использоваться тот же серверный ключ. [Документация Raster Tiles API](https://docs.2gis.com/maps/others/rastertiles/overview).
