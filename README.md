# Агент сделки — ИИ-агент «жизненных событий» для Домклик

Прототип для хакатона (номинация ROI). Клиент голосом или текстом описывает, какую квартиру ищет: город, бюджет, комнаты, пожелания. Агент:

1. **Уточняет**, если не хватает города, бюджета или числа комнат.
2. **Ипотечные программы**: спрашивает про детей и маткапитал, объясняет, подходит ли семейная ипотека и почему, сравнивает платежи и считает дальше по подходящей ставке.
3. **Финансовый помощник** по доходам, расходам и накоплениям строит стратегию накопления первоначального взноса на продуктах Сбера (накопительный счёт, вклад, облигации и фонды в СберИнвестициях) с учётом срока, ежемесячных пополнений и отношения к риску.
4. **Ищет реальные объявления на Циане** и считает справедливую цену по ближайшим похожим квартирам.
5. **Подбирает с обратной связью**: клиент отмечает «Нравится / Не то» и пишет пожелания — агент учитывает это в следующей подборке.
6. **Проверяет риски** по данным объявления.
7. **Звонит продавцу**: уточняет то, чего нет в объявлении, торгуется в рамках клиента и договаривается о просмотре.
8. **Отвечает на вопросы в любой момент** («что такое СБР?», «почему справедливая цена такая?», «сколько я переплачу?») — с числами своей сессии; системный промпт — [docs/AGENT_PROMPT.md](docs/AGENT_PROMPT.md).
9. **Новостройки**: если семейная ипотека не проходит на вторичке, агент предлагает искать и в новостройках; на каждой карточке — платёж по подходящей программе; звонок в отдел продаж застройщика, план сделки с ДДУ и эскроу.
10. **Проверка безопасности**: что видно по объявлению, и список проверок по реестрам до сделки (ЕГРН, ФССП, ЕФРСБ, доли детей; для новостроек — ЕИСЖС, эскроу, застройщик). Пока выписок нет, агент не пишет «чисто».
11. Дальше — просмотр, план сделки (ипотека, страхование, СБР, электронная регистрация) и итог: экономия клиента и доход Сбера.

- Единый системный промпт агента — [docs/AGENT_PROMPT.md](docs/AGENT_PROMPT.md)
- Разбор идей команды — [docs/IDEAS.md](docs/IDEAS.md)
- Пути развития — [docs/ROADMAP.md](docs/ROADMAP.md)

## Запуск

Установка одной командой — окружение, пакеты, модель распознавания речи Whisper small (~460 МБ) и `.env` из шаблона:

```bash
./scripts/setup.sh
```

Потом впишите в `.env` ключ `DEEPSEEK_API_KEY` (или настройки GigaChat) и запустите:

```bash
.venv/bin/uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

Откройте http://localhost:8000.

Варианты установки:
- `WHISPER_MODEL=base ./scripts/setup.sh` — модель поменьше (~140 МБ), если интернет медленный; тогда же поставьте `WHISPER_MODEL=base` в `.env`.
- `SKIP_WHISPER=1 ./scripts/setup.sh` — без модели: голос будет распознавать браузер (Chrome/Edge, нужен доступ к их облаку).
- Модель отдельно: `.venv/bin/python -m backend.stt download`. Если Hugging Face качает медленно, четыре файла (`model.bin`, `config.json`, `tokenizer.json`, `vocabulary.txt`) с https://huggingface.co/Systran/faster-whisper-small можно скачать браузером в папку `models/faster-whisper-small` и указать путь в `WHISPER_MODEL`.

Сервер сам модель не качает: если её нет, микрофон работает через браузер, а `/api/health` подсказывает команду для загрузки.

Тесты (без сети): `.venv/bin/python -m unittest discover -s tests -v`

Без ключа LLM: `LLM_PROVIDER=mock .venv/bin/uvicorn backend.main:app` — запрос и пожелания разбираются правилами, звонок идёт по сценарной стратегии. Объявления при этом всё равно реальные.

### Демо без сети

```bash
DEMO=1 LLM_PROVIDER=mock .venv/bin/uvicorn backend.main:app --port 8000
```

Объявления берутся из сохранённого среза Циана в репозитории (`backend/data/demo/`: вторичка — Казань и Москва, новостройки — Казань; 2 комнаты, 21.10.2026), звонок — сценарный. Сценарий Анны проходит все 9 шагов без интернета. С ключом LLM (без `LLM_PROVIDER=mock`) разговор и ответы ведёт модель, а объявления остаются из среза.

### Перед демо: прогреть срез объявлений

Если на площадке Циан ответит капчей, агент возьмёт последний сохранённый срез (это тоже реальные объявления). Прогрев:

```bash
.venv/bin/python -m backend.sources.cian --city Казань --rooms 2 --budget 9000000 --pages 2
.venv/bin/python -m backend.sources.cian --city Казань --rooms 2 --budget 9000000 --pages 2 --new   # новостройки
```

Срезы лежат в `backend/data/cache/` и в git не попадают.

## Откуда объявления

**Несколько площадок.** Циан и Домклик опрашиваются параллельно (список — `SOURCES` в `.env`). Одна и та же квартира с разных сайтов склеивается в одну карточку: «Есть на Циане и Домклике · на Домклике дешевле на 10 000 ₽» (`backend/sources/dedup.py`). Если одна площадка не ответила, агент работает с остальными.

**Домклик** (`backend/sources/domclick.py`) — объявления из страницы поиска (`window.__SSR_STATE__`), вторичка и новостройки, 7 городов. Сайт закрыт защитой Qrator: сначала обычный запрос, потом `curl_cffi`, потом настоящий браузер (Playwright, если установлен: `.venv/bin/pip install playwright && .venv/bin/playwright install chromium`), потом сохранённый срез. Проверка: `.venv/bin/python -m backend.sources.domclick --city Казань --rooms 2 --budget 9000000` (и `--new`).


Официального API для поиска по чужим объявлениям у Циана, Домклика и Авито нет: их API — для продавцов и агентств (свои объявления, фиды, входящие чаты). Поэтому:

- **Циан** — данные со страницы выдачи поиска, без телефонов продавцов; фото — ссылкой на оригинал. Запрос — только по просьбе клиента, 1–3 страницы, не чаще раза в 3 секунды. Сначала обычный HTTP-запрос; если Циан ответил капчей или 403 — один повтор через `curl_cffi` с TLS-отпечатком Chrome; если и он не прошёл — сохранённый срез. Проверено: Москва, Санкт-Петербург, Казань, Новосибирск, Екатеринбург, Нижний Новгород (Краснодар — код региона не проверен).
- **Домклик и Авито** — с этого компьютера не открываются (VPN с нидерландским IP: Авито блокирует по IP, Домклик закрыт защитой Qrator). Путь — отдельный сервис на сервере с российским IP; см. [ROADMAP](docs/ROADMAP.md).

Это серая зона: пользовательские соглашения площадок, скорее всего, запрещают автоматический сбор. Для прототипа с единицами запросов риск невелик; для продукта правильный источник — данные Домклика внутри Сбера.

## Что настоящее, а что симуляция

| Часть | Сейчас |
| --- | --- |
| Объявления, цены, площади, фото, районы, метро | Реальные (Циан) |
| Справедливая цена | Медиана цены м² до 8 ближайших похожих квартир (по координатам, площадь ±30%) с поправками на ремонт, год, этаж; −3% на торг; коридор — межквартильный размах |
| Звонок продавцу | **Симуляция**: продавца играет ИИ со скрытой минимальной ценой и «фактами» о квартире, или человек (режим «продавец — я») |
| Проверка рисков | По данным объявления (проверка Росреестром на Циане, апартаменты, торги, слова «доля», «наследство», «перепланировка»). Выписки ЕГРН/ФССП/ЕФРСБ не подключены |
| Финансовый план | Расчёт настоящий; ставки и доходности продуктов — допущения; «Открыть продукт» — демо |
| Ипотека | Программы и правила — настоящие (семейная ипотека с 01.10.2026, маткапитал 2026); ставки — открытые данные на октябрь 2026, в проде — предодобрение Сбера. Аннуитет, срок 30 лет |

## Архитектура

```
frontend/                статичный UI без сборки (HTML + CSS + ES-модули)
  js/app.js              контроллер: SSE-события -> чат, степпер, панели; голосовой ввод
  js/views.js            панели этапов: финансы, подборка, проверка, просмотр, сделка, итог
  js/chart.js            график накопления взноса (SVG, подсказка при наведении)
  js/call.js             экран звонка: фазы, счётчик, линейка цены, «что агент узнал»
  js/economics.js        вкладка «Экономика для Сбера»
backend/
  main.py                FastAPI: API + раздача фронтенда
  llm/                   единый интерфейс LLM: DeepSeek, GigaChat, офлайн-режим
  sources/               площадки: cian.py и domclick.py (поиск, разбор, кеш, срез, запасной путь), dedup.py (склейка дублей), base.py (формат объявления)
  agent/
    orchestrator.py      9 шагов, подтверждения клиента, сообщения клиента в любой момент
    finance.py           финансовый помощник: стратегии накопления взноса
    security.py          проверка безопасности: по объявлению + проверки по реестрам до сделки (вторичка / новостройка)
    qa.py                «спросить агента»: ответы на вопросы клиента (промпт из docs/AGENT_PROMPT.md, числа сессии, офлайн-правила)
    mortgage.py          ипотечные программы: рыночная, семейная (с 01.10.2026), маткапитал; «подходит / нет и почему»
    preferences.py       обратная связь: отметки и пожелания -> правила ранжирования
    negotiation.py       звонок: уточнение -> торг -> просмотр; рамки в коде; сценарная стратегия
    seller_sim.py        симуляция продавца для реального объявления
    tools.py             разбор запроса, справедливая цена, ранжирование, риски, ипотека, план сделки
    prompts.py           промпты
  economics.py           юнит-экономика и ROI (с финансовым помощником и без)
tests/                   GigaChat на моках, разбор Циана, звонок, финансы, обратная связь, экономика
```

Принцип: **числа считает код, LLM только разговаривает и разбирает текст.** В торге модель формулирует реплики, а код не даёт агенту предложить больше лимита клиента или отступить назад, а ИИ-продавцу — уйти ниже скрытой минимальной цены. Если модель недоступна или ответила мусором, ход делает сценарная стратегия.

### API

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/health` | провайдер LLM и подключённые города |
| POST | `/api/session` `{query}` | создать сессию |
| GET | `/api/session/{id}/stream` | SSE-поток событий агента |
| POST | `/api/session/{id}/confirm` `{kind, approved, data}` | решение клиента: `red_lines`, `family` (`data: {children, youngest_age, matcap}`), `finance`, `finance_choice`, `selection` (`data: {action: more\|proceed, liked, disliked}`), `call` (`data.mode = auto\|human`), `price`, `object`, `sign` |
| POST | `/api/session/{id}/message` `{text, liked, disliked}` | текст/голос клиента: ответ на уточнение, пожелание к подборке, заметка |
| POST | `/api/session/{id}/product` `{product, amount}` | «открыть» продукт из финансового плана (демо) |
| POST | `/api/session/{id}/seller` `{text}` | реплика живого продавца в режиме `human` |
| GET | `/api/economics?fin_enabled=true&deals=15000…` | юнит-экономика + сценарии ROI |

## Переключение на GigaChat

В `.env`:

```
LLM_PROVIDER=gigachat
GIGACHAT_CREDENTIALS=<ключ авторизации из личного кабинета, base64>
GIGACHAT_SCOPE=GIGACHAT_API_PERS        # или GIGACHAT_API_B2B / GIGACHAT_API_CORP
GIGACHAT_MODEL=GigaChat-2-Max
GIGACHAT_CA_BUNDLE=/path/to/russian_trusted_root_ca.cer   # сертификат НУЦ Минцифры
```

Если сертификата нет под рукой, для локального демо можно `GIGACHAT_VERIFY_SSL=false`. Код агента менять не нужно: оба провайдера реализуют один `LLMClient`.
